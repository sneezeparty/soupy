# Web Control Panel

Soupy ships with a FastAPI control panel that runs alongside the bot and manages it as a subprocess. **The panel is the primary way to operate Soupy** — start/stop/restart the bot, watch its log live, edit configuration, switch LLM models, and tune virtually every cadence and threshold the bot uses, all without touching the terminal. The recommended workflow is `python run_all.py`, then drive everything from the browser.

## What the panel actually does

- **Process management** — Start, stop, and restart the bot from the status bar at the top of every tab, which also shows the loaded model, uptime, and whether LM Studio, the Flux server and the Stable Diffusion backend answer. The web app spawns the bot as a subprocess via PTY; restarting the bot does not restart uvicorn, and vice versa, so you can iterate on `.env-stable` or cog code rapidly.
- **Flux server** — With `FLUX_ENABLED=true`, the Overview tab has a Flux server card: whether `flux_server.py` is running and which models it has loaded, with Start, Stop, Restart and its recent log. The panel runs the server as its own child process (`FLUX_SERVER_AUTOSTART=true` starts it with the panel), writes its output to `logs/flux_server.log`, and shows the lines in the live log marked `[flux]`. A server started by hand is shown as running outside the panel and is not stopped by it. Restarting the bot leaves the Flux server running.
- **Live log streaming** — Bot stdout/stderr is fanned out over a WebSocket (`/ws/logs`) and shown in a console drawer in real time. Also written to `logs/soupy.log` (rotating, 5MB, 5 backups).
- **Background-loop dashboard** — At-a-glance cards for each scheduled loop (Daily Post, Bluesky Engagement, Archive Scan, RAG Reindex, Soupy's Memory, Profile Refresh, Musings) showing whether each is enabled, when it last ran, when it next runs, today's progress (e.g. `2 / 2 posts`, `5 replies · 1 post · 1 repost`), and a one-click toggle that flips the corresponding env flag.
- **Runtime feature flags** — Toggle RAG-on-every-reply and time awareness, and disable individual slash commands, without a restart (these are stored in `data/runtime_flags.json` and read live by the bot).
- **Model & Personality tab** — **Chat model** shows the model in use as the model server reports it: loaded or not, the context length it was loaded with, and the chat prompt budget (`CONTEXT_WINDOW_TOKENS`) as a share of that. The form under it changes the model, the context length to load it with, or the budget. Apply first shows what will happen (which models LM Studio unloads and loads, which stay loaded and for what, what is written to `.env-stable`), then stops the bot, makes the change in LM Studio, saves, and starts the bot again. If LM Studio can't load the model, the one it unloaded is loaded again and nothing is saved. A server without LM Studio's load API gets the name saved and loads the model itself. **On the model server** lists what is loaded and what Soupy uses each model for. **Prompts** edits the nine prompt files (chat personality, search answers, article posts, 9-ball, and the image prompts) exactly as stored. Unsaved edits are kept per prompt, a save keeps the version it replaced in `prompts/backups/`, and "Use shipped default" goes back to the text that ships with Soupy. The bot reads prompts when it starts, so the editor says when a saved prompt is newer than the running bot.
- **Environment Editor** — Categorized, form-based editor for every variable in `.env-stable`. Each field has a "[?]" tooltip with a description and a placeholder showing the in-code default. Save writes only the fields you changed, and creates a timestamped `.env-stable.bak.*` backup first. Tokens and passwords are hidden until you press Show. An emptied field is left as it was; to remove a variable, delete its line in `.env-stable`. Categories include Discord setup, LLM, Stable Diffusion, Chat Behavior, Rate Limits, Vision, RAG, User Profiles, Context Window, Self-Knowledge, Daily Posts, Bluesky, Musings, Outpaint, and Web Panel theming. *Since v1.x* the editor also surfaces seven additional env vars that were previously hardcoded: `BLUESKY_MIN_GAP_MINUTES`, `BLUESKY_MAX_LIKES_PER_DAY`, `BLUESKY_MAX_FOLLOWS_PER_DAY`, `BLUESKY_ARTICLE_FRESHNESS_DAYS`, `URL_CACHE_TTL_SECONDS`, `SOUPY_LOG_MAX_BYTES`, and `SOUPY_LOG_BACKUP_COUNT`. The prompts are not edited here: their rows point to the Prompts editor, and say so when a leftover value in `.env-stable` is overriding a prompt file.
- **Stats tab** — Server and bot statistics: message volume by category over time, top channels, top users, image counts, totals across 24h / 7d / 30d windows.
- **Media tab** — Every image the bot generated or looked at, as a thumbnail grid. Filter by kind (seen by Soupy / generated) and search descriptions, prompts and names. A click opens the image in a lightbox with who posted or requested it, the channel, the time, the whole vision description or prompt, and its size and seed; the arrow keys step through the archive across pages and Esc closes it. The bot's activity log (`media/messages.jsonl`) is in a collapsible section under the grid.
- **Database tab** — One server at a time, in three views. **Messages** is the archive: search message text, image descriptions and link summaries, filter by channel, member, date range, or "has image" / "has link", and open any message to read it whole, see what Soupy saw in its image, or show the conversation around it. **Profiles** lists each member profile and Soupy's memory of itself; a profile reads as its overview plus dated items under headed sections (Personality, Lately, Family & home, Opinions, …), with a section filter, a text filter, and a search across every profile. **Maintenance** holds the profile job (start, pause, resume, cancel, its log), archive scans (run one, set the automatic interval, see recent scans), and the RAG index (chunk count, rebuild). The panel only queues the profile job; the bot runs it one pass at a time, so it needs the bot running.
- **Theming** — 30+ `WEB_COLOR_*` variables with a color-picker UI in the env editor. Set `WEB_CONTROL_PANEL_TITLE` to rebrand the page.

The panel binds to `0.0.0.0:4941` by default. Override with `SOUPY_WEB_HOST` and `SOUPY_WEB_PORT`. There are exactly two pages: `/` (the React dashboard with all the tabs above) and `/env` (the form-based env editor). The dashboard's address keeps the open tab (`/#media`, `/#database/profiles`), so a reload or a bookmark returns to it. The panel serves its own copies of React and Pico CSS from `web/static/vendor/`, so it loads with no internet access.

**Configurable without code changes.** Almost every cadence, cap, threshold, and probability the bot uses is an env var, which means it's editable in the web Environment Editor and applied on the next bot restart (one click in the panel). The handful of values that are still hardcoded are called out in their respective docs.
