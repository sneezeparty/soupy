# Changelog

All notable changes to Soupy will be recorded here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project tries to use [Semantic Versioning](https://semver.org/spec/v2.0.0.html) — though for a single-deployment Discord bot, that's a guideline, not a contract.

## [Unreleased]

### Added
- **Flux-tuned Fancy / R-Fancy prompt builders.** The `/flux` Remix view's `Fancy` and `R-Fancy` buttons previously routed through `soupy.cogs.sd`'s `build_fancy_prompt` / `build_random_prompt`, which emit the longer CLIP-style prompt shape SD wants — but Flux 2 produces sharper images from a tight ~50–75 word natural-language paragraph. Added `build_flux_fancy_prompt` / `build_flux_random_prompt` in `soupy/cogs/sd.py` that load `prompts/fancy_flux.*` / `prompts/randomprompt_flux.*` (with `RANDOMPROMPT` fallback for the latter) and respect two new env vars — `FLUX_FANCY_MAX_TOKENS` (default 120) and `FLUX_RANDOM_MAX_TOKENS` (default 140) — instead of the SD-tuned `FANCY_MAX_TOKENS`. The Flux cog's `_handle_flux_fancy` / `_handle_flux_random` switch to the new builders; the SD Remix view is unaffected. Two shipped defaults under `prompts/`; `tests/test_flux_cog_loads.py` asserts both builders are exported.

### Changed
- **Personality panel reads/writes prompts via a dedicated `/api/prompts` endpoint.** After the 2026-05-06 migration moved `BEHAVIOUR`, `BEHAVIOUR_SEARCH`, `9BALL`, `FANCY`, `RANDOMPROMPT`, and `SD_NEGATIVE_PROMPT` out of `.env-stable` into `prompts/<name>.txt`, the dashboard's Personality panel was loading them through `/api/env/get` and getting empty strings — the env editor no longer sees them, so saves silently went to keys the bot ignored. New `GET /api/prompts/get` and `POST /api/prompts/save` in `web/app.py` resolve via the same chain the bot uses (legacy env > `prompts/<name>.txt` > `prompts/<name>.default.txt`) and persist saves to `prompts/<name>.txt` with an atomic `tmp + os.replace`. CRLF is normalised to LF on save so browser-edited values don't accumulate `\r` characters that survive the bot's prompt cache. The React dashboard gains `loadPrompts()` + a `PRESET_TO_PROMPT_NAME` map; existing preset dropdown labels keep working against the new endpoint.

### Fixed
- **Slash commands no longer show up twice in the Discord typeahead.** `on_ready` used to do a guild-scoped `copy_global_to(...) + sync(guild=...)` when `GUILD_ID` was set, for instant dev iteration. Discord overlays guild-scoped commands on top of globals rather than replacing them, so once global propagation caught up, the home guild listed every command twice. `on_ready` now syncs **globally only**, then sends an empty bulk-upsert per guild (`clear_commands` + `sync(guild=...)`) to self-heal any stale guild-scoped registrations from prior runs; the clear is idempotent. Dev iteration is slower (Discord propagates within ~5min, up to ~1hr the first time), so `!synccommands` grows a `Literal["global","guild","clear-guild"]` `scope` argument — owners can still force a temporary guild sync, and `clear-guild` removes the override afterward. A new `on_guild_join` handler is deliberately a no-op for sync: newly-joined guilds receive commands via global propagation rather than another guild-scoped copy that would later duplicate.

### Docs
- **Installer caught up to the Flux backend.** The wizard predated `/flux`, so a Mac user picking "image gen on Apple Silicon" got pushed into the old SD-via-MPS path and was never prompted about `FLUX_ENABLED` / `FLUX_SERVER_URL` / Klein-Edit. Added a first-class `local_flux` mode end to end: installs `mflux` + `python-multipart` into `.venv` (no separate `.venv-sd`), prompts for host/port and the Klein-Edit toggle, writes the `FLUX_*` keys, soft-probes the backend in verification (the server is launched separately, so a "not running yet" result is informational), and reminds the user to launch `python flux_server.py` at handoff. Step 4 also populates `AVAILABLE_MODELS` from the live LM Studio model probe so the web-UI dropdown matches what's loaded, and the vision question is reworded to mention chat attachments rather than `/soupyscan`. INSTALL.md updated to match.

## [1.2.0] - 2026-06-05

### Added
- **`/flux` — local Flux image generation via mflux/MLX.** A second image backend that runs **on the same Mac as the bot** (no remote GPU host needed) via a small `flux_server.py` FastAPI process. The slash command mirrors `/sd` — text-to-image by default, image-to-image when you attach an image, plus the full Remix / Fancy / R-Keyword / Wide / Tall button panel — but is implemented as its own discord.py cog at `soupy/cogs/flux.py` and shares the main bot's `SDQueue` so Flux and SD generations serialize cleanly. Model selection is server-side: `FLUX_MODEL=schnell` (FLUX.1, 4-step distilled, 8-12 GB at Q4) or `FLUX_MODEL=flux2-klein-4b` (FLUX.2 klein). Sources for img2img are persisted under `media/flux_sources/` so the 🎚️ Strength button can re-run from the original image after Discord's attachment URL expires. Install footprint is `pip install mflux python-multipart` on the Mac that runs the model; see `requirements.txt` for the comment block and `flux_server.sh` for the launcher.
- **FLUX.2 Klein-Edit pipeline (`/flux_edit`).** Genuine prompt-driven image editing — "make this cat anime style", "set the background on fire" — that the noise-mix `/flux_img2img` path on schnell fundamentally can't do well (img2img there always skips step 0 in `mflux`'s `init_time_step = max(1, int(num_steps * image_strength))`, so at 4 distilled steps the prompt has 3 steps of denoising against a latent that's still 25% the original signal — usually enough to "close the cat's eyes", not enough to restyle it). New `Flux2KleinEdit` model slot in `flux_server.py` runs alongside the txt2img model, lazy-loaded on first edit (~5 GB extra RAM at `FLUX_QUANTIZE=4`, plus ~2-3 GB peak activations from the doubled token sequence). When `FLUX_EDIT_ENABLED=true`, `/flux <prompt> <image>` auto-routes to `/flux_edit` instead of `/flux_img2img`; falls back to noise-mix img2img if the edit endpoint errors or the configured `FLUX_EDIT_MODEL` can't load (e.g. on a `FLUX_MODEL=schnell` deployment where klein isn't downloaded). The Strength button and `🎚️` indicator are hidden for edit results since the edit path has no strength knob — image influence is via attention over concatenated reference-image tokens, not noise mixing. New env vars: `FLUX_EDIT_ENABLED`, `FLUX_EDIT_URL`, `FLUX_EDIT_MODEL` (default `flux2-klein-4b`), `FLUX_EDIT_STEPS` (4), `FLUX_EDIT_GUIDANCE` (1.0). All documented in `.env-stable.example` and `docs/ENV_REFERENCE.md`.
- **Per-model `guidance` auto-fix on the Flux server.** Distilled FLUX.2 Klein requires `guidance=1.0` (per mflux's CLI and README — schnell is CFG-distilled and uses `0.0`). When a request arrives with the legacy schnell-era default `guidance_scale=0.0` *and* the loaded model's `model_config.supports_guidance` is True (klein / dev), `flux_server.py` substitutes `1.0` and logs the override. Stops klein from producing the "barely changes the input" failure mode users hit on the first switch from schnell to klein without re-tuning env vars. Schnell remains at `0.0`.

### Changed
- **Self-reflection now runs once a day in the middle of the night, not every few hours.** `_self_md_reflection_loop` (`soupy_remastered_stablediffusion.py`) used to fire on a fixed `SELF_MD_REFLECT_INTERVAL_HOURS` (defaulting to 24h but with a 10-minute first-check warmup), which in practice meant the heavy reflection-and-anchor-regen pass could land on top of normal interaction. The loop now schedules itself to the next local-time crossing of a new `SELF_MD_REFLECT_HOUR` (0–23, default `3` = 3 AM), sleeps until then, runs one pass across all guilds (still gated by `SELF_MD_MIN_INTERACTIONS`), then sleeps until the same hour the next day. The web Environment Editor and `docs/`/`CLAUDE.md`/`ARCHITECTURE.md` were updated; the old `SELF_MD_REFLECT_INTERVAL_HOURS` knob is gone (no back-compat shim).
- **Media log now distinguishes SD, Flux, Flux-i2i, Flux-Edit, and Vision.** Every row in `media/images/index.jsonl` now carries a `source` field — `"sd"` (default), `"flux"`, `"flux-img2img"`, `"flux-edit"`, or vision via the existing `event_type` channel — written at archive time by `archive_image_bytes()` (`soupy/cogs/sd.py`) and the flux cog (`soupy/cogs/flux.py`). The web dashboard's Light Table renders per-source badges (colour-coded), caption pills, and hover tooltips via a new `imageSourceLabel(row)` helper in `web/static/dashboard/dashboard-app.js`; the hardcoded "SD" badge on every non-vision row is gone. Legacy rows (no `source` field) fall back to `"SD"` since that was the only engine when those entries were written. Two new badge variants in `dashboard.css` (`--flux` blue, `--flux-edit` amber).
- **Leaner, more focused chat context.** Two changes that cut prompt size *and* improve reply quality by not drowning the persona's "one topic, one person, reply short" instruction in marginal background. (1) **RAG now has a relevance floor.** `search_rag_chunks` sorted by cosine and returned the top `RAG_TOP_K` *regardless of score*, so up to 10 possibly-off-topic chunks were injected every reply. `fetch_rag_context_for_query` (`soupy_database/rag.py`) now drops vector hits below a new `RAG_MIN_SIM` (default `0.45`) — mirroring the floor self-knowledge chunks already had — and logs how many it dropped. New bounds-validated `settings.rag_min_sim` accessor (0.0–1.0). (2) **Right-sized the context budget in `.env-stable`:** `MAX_TOKENS` 4096 → 1024 (it's the chat-only output reserve subtracted from the 16K window, so the old value silently spent ~25% of context and let replies ramble), `RECENT_MESSAGE_LIMIT` 15 → 10, `RAG_TOP_K` 10 → 6, `RAG_CONTEXT_MAX_CHARS` 10000 → 4000, and `RAG_KEYWORD_GLOBAL_FALLBACK=0` to stop the server-wide keyword dragnet when no subject resolves. All new knobs documented in `.env-stable.example` and editable from the web Environment Editor.
- **Bounds validation on numeric settings.** `soupy/settings.py`'s `_env_int` / `_env_float` now take optional `minimum` / `maximum`; an out-of-range value logs a warning and falls back to the (known-good) default instead of crashing the bot or silently using nonsense. Applied to the settings where a bad value actually bites — `MAX_TOKENS`, `CONTEXT_WINDOW_TOKENS`, `CHAT_NUM_CANDIDATES`, `RECENT_MESSAGE_LIMIT`, `RAG_EMBED_MAX_CONCURRENT`, `RAG_REINDEX_INTERVAL_HOURS`, `SD_STEPS`, `SD_DEFAULT_WIDTH`/`HEIGHT`, the daily-post hour window and interval, the musing poll bounds and chance, and the dedup-similarity threshold. Covered by new tests in `tests/test_settings.py`. (This is the first slice of the larger "make `soupy/settings.py` the single source for all env reads" effort; the bulk migration of inline `os.getenv` reads in the main bot is still pending — see ROADMAP item 7.)
- **Image generation extracted into its own cog (`soupy/cogs/sd.py`).** Moved ~2,050 lines — the `/sd`, `/img2img`, `/inpaint`, `/outpaint` commands, all the button handlers, the `ThumbnailSelectionView` / `SDRemixView` / `EditImageModal` UIs, and the `generate_sd_image` HTTP pipeline — out of the main bot file, which drops from ~6,255 to ~4,200 lines. The shared `SDQueue` **stays** in the main module (it also dispatches `"chat"` jobs and must run before cogs load); `SDQueue.process_queue` now reaches the image functions via a lazy `from soupy.cogs import sd` import, avoiding an import cycle. The cog's slash commands register in its `setup()` via `bot.tree.add_command`. Behaviour is unchanged — the moved code is byte-for-byte identical; only its location and the way it reaches shared helpers/config changed. The cog binds shared symbols off the *live* main module (the running `__main__`, falling back to a by-name import for tests/tooling): a plain `from soupy_remastered_stablediffusion import bot` would re-execute the script — which runs as `__main__` — as a second module with a duplicate `bot`/queue that nothing drains, making `/sd` log "queued" then hang. New `tests/test_sd_cog_loads.py` guards that the cog loads, the four commands register, every queue-dispatch target resolves, and the cog binds to the live `bot` instance.
- **Atomic `.env-stable` writes.** The web Environment Editor now writes to a sibling temp file and `os.replace`s it into place, so a crash mid-save can't truncate the live config. The pre-write timestamped backup is unchanged. (`web/services/env_store.py`)

### Removed
- **🔲 2×2 candidate-grid button.** The post-generation control panel on both `/sd` and `/flux` results no longer offers the 2×2 grid that ran four low-step candidates and let you pick one to upscale. Together with the candidate-selection flow that hung off it, that's `handle_2x2_grid`, `handle_thumbnail_upscale`, `handle_regenerate_selected`, and `ThumbnailSelectionView` gone from `soupy/cogs/sd.py`; `handle_flux_2x2_grid`, `FluxThumbnailSelectionView`, and the `"2x2_grid"` branch in `process_flux_image` gone from `soupy/cogs/flux.py`; and three now-orphaned action branches (`2x2_grid`, `thumbnail_upscale`, `regenerate_selected`) gone from `SDQueue.process_queue` in the main bot. The cog-loads tests no longer assert on the removed symbols. Docs (`CLAUDE.md`, `ARCHITECTURE.md`) updated to match.

### Fixed
- **Web panel no longer swallows failures silently.** Replaced the file-read/operation `except Exception: pass` blocks in `web/app.py` (media-dir mkdir, archive/stats/dashboard reads, image-index rewrite, channel-name parsing) with `logger.warning`/`logger.debug` carrying `exc_info`. Polled dashboard reads log at DEBUG to avoid spam; genuine config-parse failures log at WARNING. The `SuppressNoisyAccess` access-log filter's fail-open branch is now documented as deliberate. Per-line JSONL parse skips remain silent `continue`s (expected on malformed lines).
- **`/soupysearch` and `/soupyimage` now distinguish a network failure from genuinely-empty results.** `perform_text_search` raises a typed `SearchBackendError` when *every* DuckDuckGo backend fails/times out (vs. a completed-but-empty search), and the image search wraps its DDGS call — both now tell the user it was a network problem and to retry, instead of "no results found" or a raw exception string. `dailypost._fetch_article_content` now logs fetch failures (it's a background loop, so no user message).

### Added
- **End-to-end test for the chat pipeline** (`tests/test_process_chat_message.py`). Drives `process_chat_message` with the OpenAI client, RAG, DB, and Discord objects mocked, asserting the happy path sends the reply, the candidate→judge selection works, RAG context is fetched and injected when enabled (and skipped when not), RAG metadata is scrubbed from the reply, and over-long replies split across multiple sends. Token budgeting, prompt assembly, scrubbing, and splitting run for real — only I/O is faked. Added `tests/conftest.py` to centralize the env-before-import preamble. Uses `asyncio.run` (no new test dependency).
- New self-knowledge **anchor** tier (`data/self_md/guild_<id>_anchor.md`). The reflection cycle now distills a small (~600 char) timeless identity statement from the core after generating it. The anchor is what gets injected into the system prompt for every reply; the larger core is no longer always-on. Topical detail (specific people, jokes, opinions on specific things) continues to be retrieved on demand via the existing self-knowledge RAG.
- Env vars: `SELF_MD_ANCHOR_MAX_CHARS` (default 600), `SELF_MD_ANCHOR_TEMPERATURE` (0.5), `SELF_MD_ANCHOR_MAX_TOKENS` (400), `SELF_MD_ANCHOR_FALLBACK_CHARS` (600). All editable from the web Environment Editor.
- Posted musings now feed into the self-reflection accumulator (the same one chat replies use). Each musing is logged as a `(self)` notable interaction tagged `[unprompted musing — mode=… — triggered by: …]`, so the next reflection cycle can grow opinions, relationships, and self-knowledge from what the bot mused about. Gated on `SELF_MD_ENABLED`; failures are swallowed so they cannot break musing posting.
- **Musings dedupe rework.** Each posted musing now persists a structured topic in two fields — `topic_subject` (what it's *about*: products, events, ideas, behaviors) and `topic_mentions` (people/handles named in it). Only `topic_subject` is used to filter candidate source messages, so people are no longer shadow-banned from the candidate pool just because they got name-checked in a recent musing.
- **Embedding-based similarity check.** When `RAG_EMBEDDING_MODEL` is set, candidate musings (archive seed, news headline, synthesis theme) are embedded and compared against the recent 15-musing window via cosine similarity; anything ≥ 0.88 is skipped before the LLM is invoked. Catches paraphrased near-duplicates that keyword filtering misses. Graceful fallback to keyword-only if the embeddings endpoint is unreachable.
- **Synthesis-mode time-bucket rotation.** Synthesis now picks its sampling window from three buckets (last 2 weeks 40%, 2-6 weeks 30%, 1.5-6 months 30%) and tells the prompt which window it drew from, so the framing matches the data it's pulling from.
- Cog-level `asyncio.Lock` serializes the entire post-and-persist pipeline so concurrent triggers (warmup, scheduled tick, `/soupymuse`) can't race on the JSONL archive.
- Background warmup task on cog load: backfills `topic_subject`/`topic_mentions` for legacy entries via one batched LLM call and pre-populates the embedding cache before the first scheduled tick fires.

### Changed
- `get_self_md_for_injection` now prefers the anchor file. Falls back to a paragraph-bounded truncation of the core (then full doc) when no anchor exists yet — so behavior is sensible from first run, and improves automatically once the next reflection cycle generates a real anchor. Net effect: system prompt drops from ~12k chars → ~6-7k chars per reply.
- The current trigger message is now wrapped in a `RESPOND TO THE MESSAGE BELOW` marker before the user/assistant merge step. Without it, the user/role merge that's needed for strict-alternation models like Gemma was concatenating the trigger onto any preceding URL content + RAG snippets + image descriptions, producing an 11k+ char user blob with the actual question buried at the end. The marker keeps the trigger findable.
- Musing prompts now require a concrete anchor — a name, a quoted phrase, a specific number, or the topic by name — so a reader can tell what Soupy is reacting to. The `news_react` mode previously forbade including the headline, which produced cryptic openers like "that ninety degrees thing keeps nagging at me" with no handle attached; that rule is now flipped to require the topic be worked in (without quoting the headline verbatim). Archive and random-thought prompts got the same anchoring instruction.
- Musing-mode weights rebalanced: `archive_reflect` 0.35 (was 0.30), `news_react` 0.20, `random_thought` 0.20 (was 0.15), `synthesis` 0.25 (was 0.35). Synthesis was over-firing on a thin archive; archive-reflect is the highest-signal mode now that subject/mentions split keeps its candidate pool diverse.
- Self-reflection feedback loop narrowed to **synthesis musings only**. The other three modes are reactions to specific external triggers and don't generalize well into self-knowledge; only the cross-message pattern-finding done by synthesis is worth memorizing. Tunable via the `_SELF_FEEDBACK_MODES` constant at the top of the cog.
- `MUSING_SYSTEM` prompt trimmed ~30%: removed duplicated anchor language (per-mode prompts say it too), all-lowercased the directives to match the persona, dropped redundant clauses.
- Topic extraction moved to *after* `channel.send()` so a slow LLM no longer delays the user-visible post; topics only need to exist by the next cycle.
- Archive writes use atomic `tmp + os.replace` instead of in-place rewrites, so a crash mid-write can't truncate the JSONL.

### Fixed
- Ignore messages from other bots in `on_message`. Soupy was reacting to Dyno-style announcement bots (and would have replied to any other bot whose post hit a `CHANNEL_IDS` channel or contained a trigger keyword), producing bot-on-bot reply chains. The Discord-standard `message.author.bot` guard now short-circuits those before LLM work or `channel.send` runs.
- Musings were repeating the same topic 3–4 times in a row. Root cause was the LLM "don't repeat these topics" hint being soft text the model ignored, combined with a wide-window random source pick that kept re-surfacing the same hot conversation. Hard-filter at the candidate-selection stage (keywords + embeddings) replaces the soft prompt hint.

## [1.1.1] - 2026-04-30

### Added
- `LOG_LEVEL` env var (default `INFO`). Controls what shows up in the terminal and the web log stream. The file at `logs/soupy.log` still captures `DEBUG` regardless. Tunable from the web Environment Editor.
- Logging policy comment block above the logging setup in the main bot, documenting what belongs at INFO vs. DEBUG vs. WARNING vs. ERROR. Roughly 5–10 lines per chat reply at INFO.

### Changed
- Demoted noisy chat-path INFO calls to DEBUG so the terminal stays readable: per-message DB connect (`Database initialized for guild …`), token-budget breakdown, history-trim notice, per-URL fetch outcomes.
- Reclassified Bluesky og:image processing logs: per-image resize/UA-blocked details → DEBUG; "could not fetch page" / "download failed (all UAs)" / "still too large after recompression" → WARNING.

## [1.1.0] - 2026-04-30

### Added
- `CHAT_FREQUENCY_PENALTY` (default `0.6`) and `CHAT_PRESENCE_PENALTY` (default `0.3`) env vars, passed to the chat completion call. They discourage the model from falling into the same speech template reply after reply. Set either to `0` to disable. Tunable from the web Environment Editor.
- Few-shot example block in the `BEHAVIOUR` system prompt — ten short style samples (greetings, insults, recall questions, political rants, etc.) to give small local models concrete shape to follow.
- Pre-commit `gitleaks` hook (`.pre-commit-config.yaml`). Run `pre-commit install` after cloning to activate. Catches secret-bearing commits before they land. Server-side secret scanning + push protection are also enabled on the GitHub repo.

### Changed
- Consolidated duplicated RAG memory rules. The longer-term memory guidance now lives once in the system prompt's `technical_instructions`; the per-turn RAG context message is a short pointer back to those rules + the actual snippets. Net prompt length is slightly shorter despite the new few-shot block.
